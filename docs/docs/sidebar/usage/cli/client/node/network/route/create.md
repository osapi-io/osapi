# Create

Add static routes to an interface.

Writes a netplan file of the interface's routes, such as
/etc/netplan/osapi-osapi0-routes.yaml for osapi0, under a netplan definition
that is the interface's own, and applies it. A default route is refused: the
interface behavior sets the gateway. An interface the host does not have is not
found. An interface that a match defines, such as cloud-init's all for en*, is
refused, because the routes would go on each interface the match takes, now and
later. An interface osapi already has routes of does not change: update replaces
them. It runs on the Debian family, and elsewhere, and in a container, reports
skipped.

```bash
osapi client node network route create [flags]
```

## Examples

```bash
# Two routes
osapi client node network route create --target web-01 --interface-name osapi0 --routes "198.51.100.0/24 via 192.0.2.1" --routes "2001:db8:1::/48 via 2001:db8::1 metric 200"

# An interface osapi already has routes of
osapi client node network route create --target web-01 --interface-name osapi0 --routes "198.51.100.0/24 via 192.0.2.1" --routes "2001:db8:1::/48 via 2001:db8::1 metric 200"
```

## Permission

It needs the `network:write` permission. `osapi token roles get --name <role>`
shows what a role grants.

## Flags

| Flag               | Description                                                                                                                                                                           | Default |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| `--interface-name` | The interface, such as eth0, or a fact such as @fact.interface.primary (required)                                                                                                     |         |
| `--routes`         | Each route as ip route writes it: &lt;destination&gt; via &lt;gateway&gt;, with metric &lt;n&gt; after it when you give one, such as 10.0.0.0/8 via 192.168.1.1 metric 100 (required) |         |
| `-T, --target`     | Target: _all, _any, hostname, or label (group:web.dev)                                                                                                                                | `_all`  |

## Global flags

| Flag               | Description                    | Default                 |
| ------------------ | ------------------------------ | ----------------------- |
| `-d, --debug`      | Enable or disable debug mode   |                         |
| `-j, --json`       | Enable JSON output             |                         |
| `-f, --osapi-file` | Path to config file            | `/etc/osapi/osapi.yaml` |
| `--url`            | URL the client will connect to | `http://0.0.0.0:8080`   |

[Output](../../../../output.md) tells how the result is printed, and what
`--json` gives.
