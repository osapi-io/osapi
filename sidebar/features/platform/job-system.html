Job system

The job system is the base of osapi. Each operation that reads or changes state runs as an asynchronous job. Thus the API server needs no privileges, and the agents run the operations on the target hosts.

How it works​

OSAPI uses a KV-first, stream-notification architecture built on NATS JetStream:

  1. The API server writes a job definition to a NATS KV bucket.
  2. The API server publishes a notification to a NATS stream.
  3. An agent receives the notification, reads the job from KV and runs the operation.
  4. The agent writes the result to a response KV bucket.
  5. The client asks the API server for the result. The API server reads it from KV.

Job routing​

Use these routing modes to send jobs to specific agents:

TargetBehavior
_anyLoad-balanced across available agents (default)
_allBroadcast to every agent
hostnameSent to a specific host
group:labelSent to all agents matching a label

Agents register with their hostname and optional key-value labels. Labels have levels with dots between them. A label target matches its prefix: for example, group:web.dev matches agents with group: web.dev.us-east.

agent.queue_groupstringjob-agentsOSAPI_AGENT_QUEUE_GROUPQueue group for load-balanced (_any) subscriptions.
